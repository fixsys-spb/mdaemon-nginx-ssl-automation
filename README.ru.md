# Автоматизация SSL для MDaemon через Nginx Proxy Manager

[🇬🇧 English version](README.md)

Автоматическое обновление SSL-сертификатов Let's Encrypt для бэкенд-сервисов (например, почтового сервера MDaemon на Windows Server 2019) с помощью Nginx Proxy Manager (Linux) и Samba.

## 📖 Описание задачи и проблемы
**Проблема:** Бэкенд-сервисы (такие как MDaemon на Windows) часто не могут самостоятельно получить сертификаты Let's Encrypt. Порты **80** и **443** обычно уже заняты фронтенд-прокси (Nginx) или заблокированы файрволом. Ручное обновление сертификатов каждые 90 дней, конвертация `.pem` в `.pfx`, импорт в хранилище Windows, правка `MDaemon.ini` и перезапуск служб — это трудоемкий процесс, подверженный ошибкам.

**Решение:** Этот репозиторий реализует архитектуру «Push-Pull»:
1. **Фронтенд (Nginx Proxy Manager):** Слушает порты 80/443, проходит проверку Let's Encrypt (ACME challenge) и безопасно получает/обновляет сертификаты.
2. **Передача файлов (Samba):** Раздает обновленные файлы сертификатов по локальной сети.
3. **Бэкенд (Windows Server):** Скрипт PowerShell по расписанию забирает файлы, конвертирует их, безопасно обновляет конфигурацию службы, перезапускает её и удаляет старые сертификаты.

## 🏗 Архитектура
* **Linux Шлюз (например, 192.168.1.3):** Docker + Nginx Proxy Manager + Samba.
* **Windows Бэкенд (например, 192.168.1.9):** Windows Server 2019 + MDaemon + OpenSSL + PowerShell.

## 🛠 Предварительные требования

### Linux-сервер (Nginx):
1. **Nginx Proxy Manager** развернут через Docker (см. `linux/docker-compose.yml`).
2. **Настроены Proxy Hosts** с получением SSL Let's Encrypt.
   * *Примечание по SAN-сертификатам:* Если у вас несколько доменов для одного сервера, перечислите их все в поле **Domain Names** через **пробел** (например, `mail.domain.com domain2.com domain3.com`). NPM сгенерирует один общий сертификат, содержащий их все.
3. **Samba** установлена и настроена для раздачи папки `/data/letsencrypt/live` (см. `linux/smb.conf.txt` и `linux/smb.conf.global.patch.txt`).

### Windows-сервер (MDaemon):
> ⚠️ **ВНИМАНИЕ (БЕЗОПАСНОСТЬ):** Шаги ниже включают небезопасный гостевой доступ SMB и SMB1 для совместимости с простой настройкой Samba. Это следует делать только в изолированной доверенной локальной сети. Для производственной среды настройте Samba с выделенным пользователем (`valid users`) и используйте `net use` в PowerShell для авторизации.
> 
> ⚠️ **ВНИМАНИЕ (ПУТИ):** В скриптах по умолчанию указан путь `D:\MDaemon`. Если ваш MDaemon установлен на диск `C:\`, вы **обязаны** изменить переменную `$MDaemonPath` в файлах `Update-Cert.ps1` и `Install-CertTask.ps1`.

1. **Включите доступ по SMB** (если используется Samba без пароля). Выполните в PowerShell:
   ```powershell
   Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters" -Name "AllowInsecureGuestAuth" -Value 1 -Type DWord
   ```
2. **Установите OpenSSL:** В Windows Server 2019 нет встроенного OpenSSL. Скачайте и установите `OpenSSL-x64-hybridCRT-4.1.0.exe` с [официального GitHub OpenSSL](https://github.com/openssl/installer/releases).
3. **Включите SMB1** (если требуется для совместимости с Samba):
   ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol-Client -All -NoRestart
   ```

## 🚀 Установка и настройка

1. Скопируйте папку `windows` на сервер MDaemon (например, в `D:\MDaemon\Scripts\`).
2. Откройте `Update-Cert.ps1` и проверьте пути:
   * `$MDaemonPath` (по умолчанию `D:\MDaemon`).
   * `$NginxShare` (сетевой путь к шаре Samba).
3. Откройте `Install-CertTask.ps1` и проверьте переменную `$CertFolder` (например, `npm-3` для Сервера 1, `npm-4` для Сервера 2). Скрипт автоматически определяет свой путь.
4. Запустите `Install-CertTask.ps1` от имени Администратора, чтобы создать задачу в Планировщике Windows на ежедневный запуск в 04:00.

## 🛠 Ручные операции и устранение неполадок

Если вам нужно проверить компоненты вручную или что-то пошло не так, используйте эти команды:

**1. Проверка связи с Samba (из Windows):**
```powershell
# Открыть сетевую папку в Проводнике
\\192.168.1.3\certs

# Или проверить через командную строку
net use \\192.168.1.3\certs
dir \\192.168.1.3\certs\npm-3
```

**2. Ручной запуск задачи по расписанию:**
```powershell
# Запустить задачу немедленно
Start-ScheduledTask -TaskName "MDaemon Cert Update"

# Проверить логи на результаты выполнения
Get-Content D:\MDaemon\Logs\NginxCertUpdate.log -Tail 20
```

**3. Проверка пути к OpenSSL:**
```powershell
# Проверить, доступен ли OpenSSL
& "C:\Program Files\OpenSSL Library\openssl-4.1\bin\openssl.exe" version
```

**4. Проверка статуса службы MDaemon:**
```powershell
Get-Service -Name MDaemon
```

## ⚙️ Как работает скрипт
* **Mutex (Защита от дурака):** Скрипт создает системный мьютекс. Если он запускается, пока работает другая копия (например, Планировщик и ручной запуск), второй экземпляр немедленно завершается, предотвращая повреждение службы.
* **Умное ожидание:** Скрипт ждет полной остановки службы MDaemon (до 2 минут). Это критически важно для серверов с медленными дисками, чтобы базы данных закрылись до обновления INI-файла.
* **Безопасная запись INI:** Используется Windows API `WritePrivateProfileString` (через встроенный C#) для обновления только конкретного ключа `CertificateHash` без повреждения остального файла `MDaemon.ini`.
* **Очистка:** Скрипт автоматически удаляет старые сертификаты Let's Encrypt для этого же домена из хранилища Windows, предотвращая их накопление.

## ⚠️ Известные проблемы и их решения
* **Ошибка `certutil: ERROR_FILE_NOT_FOUND`**: Возникает из-за пробелов во временных путях. Решено заменой на нативный PowerShell `Import-PfxCertificate`.
* **MDaemon не запускается после обновления**: Возникает при одновременном запуске двух копий скрипта. Решено с помощью Mutex и ожидания статуса.
* **Файлы не видны по SMB**: Certbot хранит сертификаты как симлинки. Samba по умолчанию их игнорирует. Применение глобального патча (`smb.conf.global.patch.txt`) включает `follow symlinks = yes` и `wide links = yes`.
* **OpenSSL не найден**: Скрипт использует умный поиск по папке `C:\Program Files`, если путь по умолчанию не совпадает.
